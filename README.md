# xray-manager-subscription

Скрипт установки и управления **Xray-core** (VLESS + Reality) и **Hysteria2** (QUIC) на Ubuntu/Debian-сервере с генерацией подписок (subscription links) для клиентов. Ставится одной командой, дальше всё управление — через интерактивное меню.

## Возможности

### Установка
- Устанавливает актуальную версию **Xray-core** (через официальный install-скрипт проекта).
- Поднимает сразу **три протокола**:
  - **VLESS TCP-Reality** (`flow=xtls-rprx-vision`)
  - **VLESS XHTTP-Reality**
  - **Hysteria2** (QUIC, отдельный сервис `hysteria-server`; пароль каждого клиента в Hysteria2 = его UUID, отзывается вместе с пользователем)
- Порты для протоколов запрашиваются **интерактивно при установке** (Enter — оставить значение по умолчанию: 443, 8443 и 36712 для Hysteria2).
- Домен маскировки (SNI) для Reality задаётся переменной `MASK_DOMAIN` (по умолчанию `github.com`).
- Включает **BBR** (congestion control), если ещё не включён.
- Ставит и настраивает **nginx + certbot (Let's Encrypt)** для HTTPS-раздачи подписок на отдельном порту (по умолчанию 9443).
- **Идемпотентная установка**: скрипт можно запускать повторно на том же сервере — перед установкой он останавливает предыдущую службу `xray`, удаляет старый nginx-сайт подписок и полностью пересоздаёт конфигурацию с нуля (без ручной чистки сервера).
- В конце установки выводит сводку по всем командам управления и **сразу открывает интерактивное меню** (`xray-menu`), если сессия запущена в терминале.

### Управление пользователями
| Команда | Что делает |
|---|---|
| `mainuser` | Показать ссылки (TCP + XHTTP + Hysteria2) основного пользователя, включая QR-коды |
| `newuser` | Создать нового пользователя сразу на обоих транспортах |
| `rmuser` | Удалить пользователя (и его UUID из всех подписок) |
| `userlist` | Список всех пользователей |
| `sharelink` | Показать ссылки существующего пользователя |
| `hy2sync` | Пересобрать конфиг Hysteria2 из текущих пользователей |
| `hy2restart` | Перезапустить Hysteria2, показать статус и ссылку main |

### Подписки клиентов
| Команда | Что делает |
|---|---|
| `subscription` | Интерактивное меню управления подписками |
| `setsubdomain` | Настроить/сменить домен для ссылок подписки (можно и после установки) |

Подписка — это один URL (`https://domain:port/sub/<token>`), отдающий клиенту base64-список ссылок сразу нескольких пользователей. Поддерживается:
- создание подписки для клиента,
- добавление/удаление клиентских ключей в существующую подписку,
- просмотр клиентов и списка подписок,
- удаление подписки.

Файлы подписок автоматически пересобираются при любом изменении (добавление/удаление клиента, смена маскировки), поэтому обновление подписки в клиентском приложении всегда подтягивает актуальные данные — новую ссылку клиенту повторно отправлять не нужно.

### Маскировка (Reality)
| Команда | Что делает |
|---|---|
| `setmask` | Меняет SNI (домен маскировки), добавляет новый shortId или меняет fingerprint (fp) по умолчанию |

При любом изменении маскировки все существующие пользователи и подписки автоматически пересохраняются с новыми параметрами — соединения не рвутся, ссылки в подписках обновляются сами.

### Маршрутизация и цепочки прокси
| Команда | Что делает |
|---|---|
| `setcascade` | Настроить каскад (proxy chaining) через внешний vless-сервер |
| `unsetcascade` | Отключить каскад |
| `routingmode` | Умный обход РФ: российский трафик идёт напрямую, остальной — в туннель |
| `disable_routing` | Отключить кастомную маршрутизацию (весь трафик — напрямую) |
| `renewgeo` | Обновить geo-базы (`geoip.dat` / `geosite.dat`) |

### Диагностика
| Команда | Что делает |
|---|---|
| `xray-check` | Проверка конфигурации, слушающих портов, статуса службы и вывод клиентских ссылок |
| `xray-menu` | Единое интерактивное меню со всеми пунктами выше |

## Быстрая установка

Одна команда на сервере Ubuntu/Debian (под root или через `sudo`):

```bash
curl -sL https://raw.githubusercontent.com/work140200-beep/xray-subscription/main/xray-manager-subscription.sh -o /tmp/xray-manager-subscription.sh
sudo bash /tmp/xray-manager-subscription.sh
```

При установке скрипт интерактивно спросит:
1. **Порт для VLESS-TCP-Reality** (Enter = 443)
2. **Порт для VLESS-XHTTP-Reality** (Enter = 8443)
3. **Порт для Hysteria2, UDP** (Enter = 36712)
4. **IP/домен для клиентских ссылок** (Enter = автоопределение)
5. **Домен для ссылок подписки** (можно оставить пустым и настроить позже через `setsubdomain`)

> Hysteria2 работает по **QUIC (UDP)** — убедитесь, что UDP-порт не закрыт фаерволом у хостера.
> Подписка отдаёт сразу все ссылки пользователя: 2 × VLESS + `hysteria2://` (поддерживается свежими клиентами: NekoBox, Hiddify, Happ, Streisand, v2rayN и др. — для самоподписанного сертификата в ссылке ставится `insecure=1`).

После установки откроется интерактивное меню `xray-menu` — дальше всё управление через него.

## Требования
- Ubuntu/Debian с systemd
- root-доступ
- Открытый 80-й порт на время выпуска сертификата Let's Encrypt (для домена маскировки и домена подписок)
- Свой домен с A-записью на сервер: сторонние SNI (`github.com`, `google.com` и т.п.) блокируются хостами на порту 443

## hardening-изменения (эта версия)

- **Маскировка под свой домен (`MASK_MODE=self`, по умолчанию).** Reality зеркалирует локальный nginx на `127.0.0.1:8444` с сертификатом Let's Encrypt вашего домена. На порту 443 виден ваш сертификат, а не `github.com`. `MASK_DOMAIN` теперь обязателен; популярные сторонние домены отклоняются. Режим `MASK_MODE=external` доступен, но он снова показывает чужой сертификат и может привести к блокировке порта хостингом.
- **Hysteria2:** сертификат Let's Encrypt вместо самоподписанного, `insecure=1` убран из ссылок, UDP-порт по умолчанию 443. Опциональный `obfs=salamander`: `HY2_OBFS=yes` (все клиенты обязаны указать `obfs-password` из `.settings`).
- **XHTTP:** случайный путь и непустой `Host` вместо `path=/`, `host=`; три shortId с возможностью ротации через `setmask` (старые остаются рабочими).
- **Сертификаты:** systemd-таймер `certbot-renew.timer` + deploy-хук перезагрузки nginx. Проблема «всё работало пару дней, потом упало» с истёкшим сертификатом устранена. Если выпуск сертификата не удался при установке, скрипт **не прерывается**: ставится временный самоподписанный сертификат, создаются все команды и меню, а команда `fixcert` повторяет выпуск и убирает `insecure=1`. Лог ошибок ACME: `/var/log/xray-certbot.log`.
- **Безопасность:** `config.json` — `root:xray 640` (ключ не читается другими пользователями), `.keys`/`.settings` — 600, токены подписок не пишутся в access-лог nginx, перед переустановкой создаётся бэкап в `/root/xray-manager-backups/<timestamp>`.
- **Supply chain:** версии зафиксированы (`XRAY_VERSION`, `HY2_VERSION`), бинарник Hysteria2 проверяется по `hashes.txt` релиза.
- Удалено блокирующее правило `geoip:cn` из маршрутизации по умолчанию.


## Структура на сервере
```
/usr/local/etc/xray/config.json     — конфигурация Xray
/usr/local/etc/xray/.keys           — ключи Reality, UUID и т.д.
/usr/local/etc/xray/.settings       — настройки портов (вкл. hy2_port, subs_port), fingerprint
/usr/local/etc/xray/lib.sh          — общая библиотека функций
/usr/local/etc/xray/subscriptions/  — данные подписок (JSON)
/usr/local/bin/hysteria             — бинарник Hysteria2
/etc/hysteria/config.yaml           — конфиг Hysteria2 (auth userpass: email = UUID)
/etc/hysteria/{cert.pem,key.pem}    — сертификат Let's Encrypt домена маскировки
/etc/nginx/sites-available/xray-mask — локальный TLS-источник для Reality (self-режим)
/etc/systemd/system/certbot-renew.timer — автопродление сертификатов
/usr/local/bin/{mainuser,newuser,rmuser,userlist,sharelink,
                 setcascade,unsetcascade,setmask,routingmode,
                 disable_routing,renewgeo,subscription,
                 setsubdomain,xray-check,xray-menu,
                 hy2sync,hy2restart,fixcert}
```
